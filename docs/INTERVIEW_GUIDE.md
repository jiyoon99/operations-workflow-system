# 면접 시연 가이드

## 실행과 로그인

프로젝트 폴더에서 `DEMO-START.bat`을 더블클릭한다. 이미 실행 중이면 해당 화면을 연다. 기본 주소는 `http://127.0.0.1:5110`이며, 포트가 사용 중이면 다음 번호를 사용한다.

- 관리자: `admin` / `12345678`
- 조회 담당자: `viewer` / `12345678`
- 처음 상태로 복구: `DEMO-RESET.bat` 더블클릭.
- 종료: `DEMO-STOP.bat` 더블클릭.

이 계정은 가상 데이터가 있는 로컬 데모 전용이다. 서버를 새로 시작하면 새 DB를 만들며, 이전 시연 파일과 운영 데이터는 수정하지 않는다. 패키지가 설치된 이 PC에서는 시연에 인터넷이 필요하지 않다. 자동 수집·문자 발송을 끄고, 서버의 Requests 기반 외부 HTTP 호출도 차단한다.

## 5분 설명 순서

### 0:00~0:40 프로젝트 소개

> 중고 PC 유통 업무에서 사용하는 사내 웹 도구입니다. GPT와 Claude를 활용해 기획부터 화면, 서버, 데이터 연동, 테스트와 운영까지 혼자 개발했습니다. 매입부터 출고와 A/S까지 한 자산의 업무 흐름을 연결하는 데 집중했습니다. 지금 보여드리는 것은 개인정보를 제외한 가상 데이터입니다.

### 0:40~1:30 대시보드와 매입

대시보드에서 재고·주문·매출을 보여주고, **매입 → 자산**으로 이동한다. 자산을 하나 열어 모델, 매입가와 이력을 보여준다.

> 관리 단위를 자산번호로 잡았습니다. 같은 모델이라도 매입가, 상태, 수리 이력이 다르기 때문에 제품 한 대 단위로 주문과 이력을 연결합니다.

### 1:30~2:30 주문과 셋팅

**주문관리 → 셋팅** 순서로 이동한다. 대기·준비·제작·검수 단계에 서로 다른 데모 주문이 있다. 처음에는 화면을 설명하고, 직접 조작은 준비 중인 주문 한 건만 대상으로 한다.

> 단계별 완료 여부뿐 아니라 담당자와 시간을 기록합니다. 제작 전에 검수가 끝나는 등 잘못된 순서는 서버에서 제한하고, 주문에 실제 자산을 매칭합니다.

### 2:30~3:40 대표 사례: 유상 A/S 결제 잠금

**A/S → 진행 상황 → 결제 전**으로 이동한다. `데모 고객 1`은 수리는 완료했지만 유상 금액이 미입력된 건이다. `열기`를 눌러 상세와 회수 구성품을 보여준다.

> 유상으로 바꾼 뒤 금액을 입력하지 않으면 청구액은 0원입니다. 이것을 무상으로 해석하면 결제 전에 출고될 수 있어서, 금액과 결제 상태를 별도로 판단하도록 구현했습니다. 회수 구성품도 접수부터 반송까지 이어서 확인합니다.

직접 값을 바꿔 보았다면 다음 연습 전에 `DEMO-RESET.bat`으로 복구한다.

### 3:40~4:30 정산과 권한

**설정 → 매출 / 실적**에서 기간 실적과 판매 전표를 보여준다. 권한 질문이 나오면 로그아웃 후 `viewer` 계정으로 로그인해 보이는 메뉴가 달라지는 것을 보여준다.

> 직원별로 업무에 필요한 메뉴를 주고 API에서도 권한을 확인합니다. 판매가뿐 아니라 매입 원가와 수리비, 수수료를 함께 다루도록 확장했습니다.

### 4:30~5:00 AI 활용과 회고

> GPT와 Claude를 활용해 개발했습니다. 제가 맡은 일은 실제 업무 요구를 정리하고, 구현 결과가 그 규칙에 맞는지 확인하고, 문제가 생기면 원인을 좁혀 수정하는 것까지 포함합니다. 예를 들어 방금 보신 유상 금액 미입력 사례처럼 정상 흐름 밖의 상황도 검증 대상으로 다뤘습니다.

도구별 역할·프롬프트를 질문받으면 본인이 실제로 사용한 과정을 설명한다. 기억하지 못하는 지시문이나 측정하지 않은 절감률을 만들어 말하지 않는다.

## 당일 준비

1. `DEMO-RESET.bat`으로 새 데이터를 준비하고 관리자 로그인.
2. 브라우저 확대율 100%로 대시보드를 열어 둔다.
3. A/S 결제 전 건과 설정의 매출 / 실적 위치를 한 번 확인한다.
4. GitHub README와 이 가이드를 별도로 열어 둔다.
5. 창이 닫히거나 연결이 끊기면 `DEMO-START.bat`을 다시 실행한다.
